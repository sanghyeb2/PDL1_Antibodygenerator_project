- 현재 독립 세션의 main PID/PGID는 **375**. 결과 루트 `active_process.json`에 실제 명령·PID·로그·코드 SHA256을 기록했다. 다음 확인 때는 실제 프로세스를 대조한다.
- `구조평가.py resume-main --ids CTRL_atezolizumab --sampling 1000 --refine 100`으로 실행했다. 설치된 HADDOCK의 rigidbody job factory를 해당 worker에서만 감싸, 검증된 출력은 복사하고 누락된 job만 실행한다. 설치 라이브러리 파일은 변경하지 않는다.
- 저장된 **753개 모두** PDB END, topology 전체 원자 구성, 유한 좌표, HADDOCK 에너지 항목 및 SHA256 검사를 통과했다. 재시작 삭제 범위 밖의 `resume_rigidbody_cache/`에도 보관했다. 잘린 PDB를 거부하는 검사도 통과했다.
- 공식 원본 job factory가 생성한 1,000개 모델의 인덱스·시드(기본 42 + 인덱스)를 그대로 유지한다. 재개 로그에서 `Official CNS jobs: 247 new; 753 verified outputs restored`, `Running CNS Jobs n=247`을 확인했다. 표본 수·정제 수·점수 계산법은 바꾸지 않았다.
- 각 파일 SHA256/인덱스/시드와 factory 소스 해시는 WSL 원본 폴더 `resume_rigidbody.json`에 보존한다. PC 종료 당시 전체 압축 백업도 그대로 유지한다.
- 현재 상세 로그: `/root/.cache/pdl1-structure/runs/main/CTRL_atezolizumab/resume_execution.log`.
- 전체 부모 로그: 결과 루트 `main_resume_driver.log`. 완료 후 공식 scoring/io 내보내기와 후속 정제/클러스터를 끝내고, completed 기록을 저장한 뒤 `run-main`이 이 후보를 캐시로 건너뛰어 분석·나머지 41쌍을 이어간다.
- 아직 본 도킹 완료는 0/42. 완료 점수/최종 순위로 해석하지 않는다. 같은 작업을 중복 실행하지 않는다.

## 이전 상태: PC 종료를 위해 저장 후 일시정지

사용자가 컴퓨터를 꺼야 한다고 요청하여 **도킹 전용 그룹 313을 동결 → 전체 작업 폴더 압축 → 압축 읽기 검증/디스크 반영 → TERM/CONT로 종료**했다. 마지막 `ps`/`pgrep`에서 해당 main/HADDOCK/CNS 작업이 없음을 확인했다. **아래의 실행 중/PID 설명은 종료 전 이력이며, 현재 계산을 다시 시작하지 않는다. 사용자의 재개 요청을 기다린다.**

- ColabFold 43개 구조와 입력/시드/설정/환경은 전부 디스크에 보존되어 있다. 재예측하지 않는다.
- 첫 atezolizumab의 완료 단계는 `0_topoaa`, 중단 단계는 `1_rigidbody`다. 정지 시 rigidbody PDB 파일 **753개**가 있었고 일부는 생성 도중일 수 있으므로 753개 완성 포즈로 간주하지 않는다.
- 본 도킹 완료 후보는 아직 0/42. 순위/PRODIGY 완료 결과로 표기하지 않는다.
- 압축 백업: 결과 루트 `checkpoints/CTRL_atezolizumab_shutdown_20261115.tar.gz`, **62,648,198 bytes**.
- SHA256: `2bdddeaa5dffa6a97384694c33ec310f33b64ca659fa38becf213dab63809d89`.
- 상세 기록: 결과 루트 `shutdown_checkpoint_20261115.json`. WSL 원본 디렉터리도 삭제하지 않고 보존했다.
- 재부팅 뒤 **CONT -313을 실행하지 않는다.** 옛 PID는 종료됐고 재사용될 수 있다.
- 재개 시 실제 프로세스 유무부터 확인하고 원본/백업을 보존한 채 설치된 HADDOCK의 restart 동작을 검토한다. 공식 `--restart 1`은 선택 단계 이후 폴더를 삭제하고 재계산하므로 무작정 실행하지 않는다. 진행 중 포즈의 재사용이 공식적으로 가능한지 먼저 확인하고, 불가능하면 백업을 유지한 채 해당 단계만 재계산한다. 완료된 topology와 ColabFold 구조는 재사용한다.

- WSL Ubuntu-24.04, main Python PID **313**, 현재 도구 세션 **30137**. 재개 시 실제 프로세스부터 확인하고 중복 실행하지 않는다.

Ruling: 기존 파일럿 64/16의 낮은 샘플링을 본 비교에 사용하지 않고, 모든 42개 후보에 1,000/100의 동일 예산을 적용한다. 전체 ECD를 탐색하는 제한된 계산 예산이므로 탐색적 포즈 비교로 해석하며 결합 여부를 확증하지 않는다. 대조군의 알려진 접촉 복원 정도도 함께 보고한다. 필요시 더 큰 예산 비교는 별도 실행으로 분리하고 기존 점수와 혼합하지 않는다.

## 실행 시간과 상태

기존 실험 구조 파일럿은 64/16에 약 7분 14초(강체 2분 7초, flexref 4분 32초)였다. 본 비교는 더 큰 220 aa 항원과 1,000/100을 사용한다. **전체가 수십 시간~수일 규모일 수 있으며 첫 본 대조군 완료 후 실측값으로 갱신한다.** 아직 본 대조군/생성 후보 도킹 점수는 완료되지 않았다.

도킹은 현재 로컬 CPU에서 진행하므로 Colab 런타임과 독립적이다. 로컬 PC 종료/절전 시 계산이 중단될 수 있다. Colab 결과와 환경 로그는 이미 로컬 ZIP에 보존했다.

## 이어서 확인할 때

1. WSL에서 현재 PID와 CNS 프로세스, `/root/.cache/pdl1-structure/runs/main/CTRL_atezolizumab/execution.log`를 확인한다.
