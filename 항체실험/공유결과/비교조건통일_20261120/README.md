# 비교 조건 통일 — 2026-11-20

**4개 비교 입력 준비와 topology 전처리 검사 완료. 전체 도킹은 시작하지 않았다.** 기존 main42, 대조군 검증, 점검 결과는 모두 보존했다.

두 대조군 각각에서 **실험 Fv 대 ColabFold Fv**를 비교할 수 있도록 아래 조건을 맞췄다. 서로 다른 두 항체 사이의 항원 좌표까지 하나로 합친 실험은 아니다. 각 항체 쌍은 해당 실험 복합체의 동일한 PD-L1을 사용한다.

## 맞춘 항목

- **서열과 관측 잔기 범위:** 각 쌍의 잔기 번호·아미노산이 동일하다. durvalumab VL 서열 첫 잔기는 실험에서 관측되지 않아 양쪽에서 똑같이 제외했다. 완전한 VH/VL 서열 전체를 새로 모델링한 실험이 아니다.
- **항원:** 각 쌍에서 같은 실험 PD-L1의 서열·좌표·PDB 파일 해시를 사용한다. 기존 실험/예측 항원 사이의 GLU/GLN 위치29 차이를 제거했다. 공통 실험 항원의 위치29는 GLU이다.
- **항체–항원 결합 제약(AIR):** 분리된 Fv에서 양쪽 모두 노출된 CDR 잔기의 교집합을 사전에 고정했다. 항원의 접근성 집합도 공통 항원에서 계산했다. 복합체 상태의 매몰 면이나 정답 접촉으로 epitope를 지정하지 않았다. 쌍 내 `ambig.tbl`은 바이트 단위로 같다.
- **양성자화:** `autohis=false`, 모든 HIS를 중성 HISE(NE 쪽 proton)로 지정했다. 기존 H/D와 OXT를 제거하고 `hydrogen_build="all"`로 다시 처리했다. 양쪽에 같은 비전하 말단 정책을 적용했다. topology seed42, 본 도킹 계획 seed42/CPU6/1000·100 예산을 기록했다.
- 처리된 PSF에서 모든 원자의 잔기·종류·질량·부분전하와 결합 연결을 비교했다. 각 HIS의 HE2 존재·HD1 부재·잔기 전하0도 실제 출력에서 확인했다. 이는 계산 조건 통일을 위한 가정이며 생리적 pH에서의 실제 protonation을 측정한 결과가 아니다.

## 실제 검사 결과

- **atezolizumab:** 각 입력 총 원자 **3,521개**, 전체 모델상 전하 **-1e**, 원자별 전하·질량·결합 연결 일치. 고정 AIR 잔기 수는 H9/L7/항원49개이다.
- **durvalumab:** 각 입력 총 원자 **3,621개**, 전체 모델상 전하 약 **0e**, 원자 종류·전하·질량·결합 연결까지 일치. 고정 AIR 잔기 수는 H10/L7/항원57개이다.
- 두 쌍 모두 항원 PDB·AIR 파일·양성자화 설정 파일이 정확히 일치한다. 일치 여부와 출처/설정 해시는 `state.json` 및 각 `normalization_report.json`에 있다.

## 의도적으로 보존한 구조 차이

atezolizumab의 H101–H102 peptide는 실험에서 omega 약 **174.56°(trans)**, 예측에서 **-8.97°(cis)**이다. 그에 따라 CNS는 H101 carbonyl C의 타입을 각각 **C/CCIS**로 지정했다. 원자·전하·질량·결합 연결은 같지만 이 force-field 원자 타입은 같지 않다. 보고서의 엄격한 `identical` 값은 이 쌍에서 **false**이며 숨기지 않았다. 해당 타입과 실제 omega의 대응도 검사했다.

입력 구조의 차이를 검사하려는 목적에 맞춰 예측 구조를 실험 conformation으로 임의 수정하지 않았다. 따라서 **양성자화·전하를 통제한 입력 구조 비교**라고 표현하며, 모든 force-field 파라미터가 같은 순수 좌표 비교라고 부르지 않는다. 이 cis/trans 차이를 제거하는 재설계는 별도 실험이다.

또한 **Fv 내부 구조 유지 제약**은 같은 `restrain_bodies` 알고리즘과 seed917로 생성하지만 입력 구조별 거리 목표를 보존하므로 파일이 다르다. 실험 Fv의 거리값을 예측 Fv에 강제로 부여하면 검증 대상인 구조 차이를 줄일 수 있어 그렇게 하지 않았다. 동일하게 만든 것은 항체–항원 AIR 결합 제약이다.

## 파일·재개 방법

- `state.json`: 준비 완료/도킹 미시작 상태와 두 쌍의 상세 검사 결과.
- 각 대조군의 `normalization_report.json`: 엄격한 타입 일치 여부, 서열·항원·AIR·양성자화·전하·결합 일치와 남은 구조 차이.
- `experimental/`, `predicted/`: 표준화한 입력 PDB, AIR/내부 거리 제약, 전체 `workflow.cfg`, topology 전처리 설정 및 검증된 출력/해시.
- 전체 항체 원서열과 비교에서 관측된 잔기 범위는 구분한다. 입력 파일의 번호는 기존 전역 H/L 대응을 유지한다.

코드 진입점은 `구조평가.py prepare-controlled-controls`이다. 이는 **입력 준비·topology만** 실행한다. 완료 전처리는 해시를 검사해 재사용한다. 4개의 새로운 topology 작업만 수행했으며, 이미 끝난 도킹·모델 예측은 재실행하지 않았다.

다음 전체 도킹은 고정된 `workflow.cfg`를 그대로 사용해야 한다. 일반 `dock` 명령으로 이 폴더의 입력·제약을 다시 생성하지 않는다. 기존 조건과 입력·제약·양성자화가 바뀌었으므로 새 대조군 baseline이 필요하며, 이전 DockQ를 이 조건의 결과로 대체하지 않는다. 아직 새 도킹 결과나 성능 향상 수치는 없다.
