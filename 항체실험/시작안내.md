# 실행 파일은 두 개만 보면 됩니다

**MAGE.py**: 학습 전 원본 MAGE의 설정·모델 로딩·항체 생성·VH/VL 분리·검증 NLL 평가를 한 파일에 모았다.

**LoRA.py**: 설정·데이터 검사·유사 항체 분할·LoRA 초기화·학습·누적 gradient·검증·조기 종료·최적 모델 저장·생성·NLL 평가·시각화까지 한 파일에 모았다. MAGE.py나 이전 개별 스크립트를 import하는 래퍼가 아니다.

맨 위 `CONFIG`, `TRAIN_CONFIG`, `SPLIT_CONFIG`와 경로 상수를 수정하면 된다. 명령행 인자가 있으면 그 값이 우선한다. 파일 안의 한글 구획 주석을 따라 실행 흐름을 읽으면 된다.

## 바로 실행

프로젝트 루트에서 실행한다. 가상환경을 별도로 activate하지 않아도 기존 `.venv-mage-gpu`의 Python을 자동 선택한다. 파일의 절대 경로로 실행해도 입력 경로는 스크립트 위치를 기준으로 찾는다.

```powershell
# 원본 MAGE로 PD-L1 항체 1쌍 생성
python 항체실험/MAGE.py

# 학습된 최적 LoRA로 PD-L1 항체 1쌍 생성
python 항체실험/LoRA.py

# 기존 본학습 결과 요약 (GPU 사용 안 함)
python 항체실험/LoRA.py --mode summary

# 기존 결과 시각화 (재학습 안 함)
python 항체실험/LoRA.py --mode plot --show

# 동일 검증셋 21쌍의 NLL을 실제 모델로 계산
python 항체실험/MAGE.py --mode evaluate
python 항체실험/LoRA.py --mode evaluate

# 경로/의존성 확인 (모델 가중치 GPU 로딩 없음)
python 항체실험/MAGE.py --mode check
python 항체실험/LoRA.py --mode check
```

기본 항원은 선별 CSV에 있는 PD-L1 서열, 시드는 42다. 생성·평가 결과는 `생성결과` 아래 날짜별 새 폴더에 저장한다. 생성 raw output과 JSON은 항상 보존하며, 기본 서열 검사를 통과하면 FASTA도 저장한다. 이 검사는 결합력 검증이 아니다.

## 새로 학습할 때만

```powershell
# 원본 MAGE에서 새 어댑터를 학습하고 최적 결과 시각화까지 실행
python 항체실험/LoRA.py --mode train

# 다른 데이터/조건으로 새 분할을 만들 때
python 항체실험/LoRA.py --mode split --output 항체실험/학습결과/새분할 --split-seed 42

# 그 분할로 학습할 때
python 항체실험/LoRA.py --mode train --split 항체실험/학습결과/새분할 --output 항체실험/학습결과/새실험
```

기본값: rank 8 / alpha 16 / dropout 0.05 / lr 1e-4 / accumulation 8 / 최대 20 epoch / patience 4. 기존 85/21 분할을 재사용하며, `SPLIT_CONFIG`는 새 분할을 만들 때 적용된다. 기존 분할을 바꾸려면 새 출력 경로로 split을 실행한다. 기존 결과 폴더는 덮어쓰지 않는다.

시드·실행 설정·epoch별 ID 순서·코드/데이터/모델 해시는 각 학습 결과에 기록한다. 소스 파일 통합으로 과거 hash와 현재 hash는 다르므로, 분할은 원본 데이터 hash와 실제 분할 재계산·CSV 행 내용으로 검증한다. 과거 기록은 보존했다.

## 이제 폴더를 보는 순서

- `MAGE.py`, `LoRA.py`: 평소 확인할 두 실행 파일.
- `학습결과`: 분할·본학습·최적어댑터·시각화. 기존 최적 모델은 `본학습_20261108_시드42/최적어댑터`다.
- `생성결과`: 생성/평가마다 새로 생기는 결과.
- `검사`: 통합 코드의 테스트.
- `이전코드`: 이전 개별 스크립트 보관. 현재 실행에서 사용하지 않는다.
- `설명서`: 과거 실험 방법과 논문 참고 기록. 현재 명령은 이 시작안내를 따른다.
- `외부코드`, `캐시`: 모델 라이브러리와 작업용 캐시.

PyTorch/Transformers/PEFT와 외부 ProGen 구현은 라이브러리로 사용한다. 외부 패키지 전체를 소스에 복사하지 않고, 프로젝트의 처리 흐름을 두 파일에 직접 넣었다. 기존 환경에는 필요한 패키지가 설치되어 있다. 패키지를 자동 설치/변경하지 않으며, 현재 버전은 `requirements-lock.txt`에 기록했다.

다른 컴퓨터에서는 원본 MAGE·CSV·ProGen 소스를 같은 상대 위치에 준비하고 CUDA에 맞는 PyTorch 환경을 설치해야 한다. 경로는 두 파일 맨 위에서 수정할 수 있다.

검사 명령:

```powershell
& MAGE_ab_generation/.venv-mage-gpu/Scripts/python.exe -X utf8 -m unittest discover -s 항체실험/검사 -p 'test_*.py' -v
```

기존 최적 checkpoint는 epoch 3, 검증 NLL 0.6587138322다. 모델 선택에 사용한 검증셋의 결과이며 독립 test 성능이나 실제 PD-L1 결합력은 아니다.

## 생성한 항체 1,000쌍씩 비교하기

2026-11-11 실험은 `생성결과/PDL1_생성비교_20261111_시드42`에 저장한다. 원본과 LoRA 각각 **1,000번의 생성 시도**, batch 4, seed 42, top-p 0.9, temperature 1, 새 토큰 최대 250이다. 매 배치의 시드는 `42 + 배치 시작 인덱스`로 정한다. 동일 조건에서 완료 배치를 재사용하며, 조건이 다르면 재개를 거절한다. 실행을 두 번 반복하지 않는다.

```powershell
# 전체 생성 후 분석. 기존 완료 배치는 그대로 사용한다.
python 항체실험/LoRA.py --mode campaign --max-new-tokens 250

# 생성은 다시 하지 않고 전체 분석/그림을 갱신한다.
python 항체실험/LoRA.py --mode analyze

# 이미 저장된 점수로 즉시 중간 그림과 예시 서열 10쌍을 본다.
# 추가 생성/번호 매기기/OASis 계산은 하지 않는다.
python 항체실험/LoRA.py --mode preview

# 생성 진행 중 번호 매기기만 미리 실행하고 캐시한다.
python 항체실험/LoRA.py --mode analyze --annotation-only

# 공식 DB가 준비되었으면 완료된 새 서열만 주석·OASis 캐시에 추가한다.
# 이 명령은 최종 후보/그림을 만들지 않는다.
python 항체실험/LoRA.py --mode analyze --score-available --oasis-workers 4
```

생성 원시 토큰·문자열·실패 원인은 모델별 `원본배치`와 `raw_candidates.json`에 남긴다. 실패를 빼고 1,000개를 채우는 실험이 아니다. 메모리 진단으로 첫 배치를 완료하기 전에 중단한 batch16 실행은 `배치16_메모리진단`에 따로 기록했다. 실제 비교에는 포함하지 않는다.

실제 실행은 GPU의 여유를 확인한 뒤 두 모델 프로세스를 겹쳐 진행했다(총 GPU 메모리 약 5.6GB). 배치 크기·토큰 수·시드 규칙은 동일하며 각 프로세스의 난수 상태는 독립적이다. 실행 순서만 달라졌고 `execution_schedule.json`에 기록했다. `campaign` 명령 자체는 차례로 실행하므로 메모리가 작은 환경에서도 쓸 수 있다. 동일 출력 폴더에서 이미 생성 중이면 OS 파일 잠금으로 두 번째 쓰기를 막고 `already_running`을 출력한다. 프로세스 종료 시 잠금이 자동 해제되어 같은 명령으로 재개할 수 있다.

CPU 분석도 생성과 겹쳐 진행할 수 있다. `score-available`은 성공/실패를 포함한 현재 시도 집합을 읽되, 아직 점수가 없는 고유 서열쌍만 공식 BioPhi로 계산한다. OASis는 독립 CPU 프로세스 4개로 계산하며 결과 수치는 동일한 공식 API에서 얻는다. 전체 생성 후 분석은 캐시를 재사용한다. 같은 실험의 분석은 별도 OS 잠금으로 직렬화하며, 이미 분석 중이면 후속 분석이 대기한다. JSON은 임시 파일을 완성한 뒤 교체한다. 최종 도표는 전체 시도 수를 검증한 뒤에만 작성한다.

분석 결과는 같은 실험의 `분석` 폴더에서 확인한다.

- `생성항체_주요분석.png/.svg`: 단계별 통과 수, **선별 전** OASis 분포, train85 대비 VH/VL·HCDR3·영역별 거리, VH/VL 유전자 사용.
- `생성항체_보충분석.png/.svg`: CDR3 길이, 생성 집단 내부 거리, 원본 MAGE 학습 자료 대비 거리, known106 대비 유사도.
- `전체후보_단계별지표.csv`: 실패를 포함한 모든 시도와 기본 검사·ANARCI·humanness·추가 선별 단계의 통과 여부/사유. `stage_summary.json`은 집계.
- `MAGE_최종후보.csv/.fasta`, `LoRA_최종후보.csv/.fasta`: 10+5+5 방식 최종 후보. 기준 충족 수가 부족하면 부족 수를 보고하고 기준을 낮추지 않는다.
- `*_선택후보_HCDR3정렬.png/.txt`: 선택 후보와 가장 유사한 알려진 PD-L1 양성의 HCDR3 비교.
- `generation_settings.json`, `annotation_settings.json`, `oasis_settings.json`, `analysis_provenance.json`: 시드·모델/데이터 해시·도구/DB·기준을 기록.

서열 분포는 반복 생성된 시도를 포함해 집계하고, 중복 쌍 수를 별도로 공개한다. 최종 후보는 VH/VL 쌍 중복을 제거한다. 주요 F는 논문 Figure 1F처럼 전체 VH/VL이 가장 가까운 참조를 먼저 고른 뒤 그 참조의 영역별 차이를 계산한다. CSV에는 영역마다 독립적으로 찾은 최소거리도 별도 열로 제공한다. 거리 동률은 참조 전체 서열의 사전순으로 처리한다. OASis 백분위는 사람 레퍼토리와의 유사성 지표이며 결합 확률이 아니다. 최종 후보에도 PD-L1 결합이 확인되었다는 의미를 부여하지 않는다.

### 분석 환경과 논문 기준

모델은 기존 Windows CUDA 환경을 사용하고, ANARCI/HMMER/BioPhi 분석은 WSL `Ubuntu-24.04`의 `/root/.cache/pdl1-analysis/env/bin/python`에서 실행한다. 이 컴퓨터에는 준비했다. 다른 컴퓨터에서는 Linux/WSL에 `analysis-environment.yml`의 패키지와 HMMER를 설치하고 `LoRA.py`의 `ANALYSIS_PYTHON`을 맞춘다. BioPhi는 공식 v1.0.9 커밋을 사용한다. BioPhi의 웹 앱용 선택 의존성은 분석 API에 필요하지 않으며 설치하지 않았다.

공식 OASis v1 데이터: https://zenodo.org/records/5164685/files/OASis_9mers_v1.db.gz?download=1 . 압축 약 6.5GB, 해제 약 23GB다. 압축 MD5 `28fa18135b3ef1710970f72b5953cbc5`를 검증한 뒤 `캐시/분석도구/OASis_9mers_v1.db`에 두고, 검증 기록 `oasis_database_verified.json`을 함께 보존한다. 분석은 검증 기록이 없으면 중단한다. 대용량 DB·가상환경·생성 결과는 Git에 포함하지 않는다.

ANARCI는 human germline, IMGT 번호로 VH/VL의 FR1·CDR1·FR2·CDR2·FR3·CDR3·FR4와 100 aa 이상을 검사한다. 공식 BioPhi의 paired OASis percentile을 `min_fraction_subjects=0.10`으로 계산하고 0.70 이상을 통과시킨다. 이는 두 체인 백분위의 단순 산술평균으로 직접 구현한 값이 아니다.

추가 후보 선별은 로컬 원본 `selection_pipeline_24-03-16.ipynb`를 따른다. VH V-germline identity는 0.85 이상 1 미만, 학습 자료와 동일한 HCDR3를 제외한다. 상위 5개 VH V 유전자의 identity 20/80% 위치에서 10개, 알려진 양성과 HCDR3 유사도가 높은 5개, VH 유사도가 높은 5개를 고른다. 후자의 두 그룹은 VH와 HCDR3가 모두 90% 이상인 후보를 제외한다. 작은 유전자 그룹은 원본 노트북의 `int(n*p)-1` 규칙을 유지하되 중복 선택을 보충하지 않는다.

PD-L1에 적용한 차이는 명시한다. 원본 MAGE 학습 자료와 LoRA train85에서 HCDR3 일치를 각각 검사하고, RBD SAbDab/CoV-AbDab 대신 알려진 PD-L1 양성 106쌍을 후보 근접성 기준으로 쓴다. known106에는 검증셋 21쌍도 포함하므로 이 유사도는 독립 평가 지표가 아니다. 신규성은 train85 및 원본 MAGE 학습 자료에 대해 별도로 표시한다. RBD의 절차를 PD-L1에 적용한 것이며 RBD 결과 수치 자체를 재현하는 실험은 아니다.
